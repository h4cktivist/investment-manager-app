# Investment Manager

Учёт инвестиций в инструменты российского фондового рынка: сделки и выплаты,
календарь купонов и дивидендов, метрики доходности и риска, облигационные
расчёты и сравнение с индексами Мосбиржи.

Данные о рынке берутся из **MOEX ISS API** — публичного и бесплатного.

```
investment-manager/
├── backend/     FastAPI + SQLAlchemy 2 + Alembic + PostgreSQL
├── frontend/    React 18 + TypeScript + Vite + TanStack Query + Recharts
└── docker-compose.yml
```

---

## Быстрый старт

```bash
cp .env.example .env
docker compose up -d --build      # поднимет PostgreSQL и бэкенд на :8000

cd frontend
npm install
npm run dev                       # фронтенд на :5173
```

Открыть <http://localhost:5173>. Документация API — <http://localhost:8000/api/docs>.

API отвечает сразу после миграций; история индексов-бенчмарков с 2013 года
догружается фоновой задачей (полторы-две минуты при первом запуске). Дальше:

1. Создать портфель и завести операции на странице **Сделки** — инструмент
   ищется прямо на Мосбирже по тикеру или названию.
2. История цен и купонные графики по вашим бумагам догрузятся в фоне (1–3 минуты).
3. Дашборд наполнится данными.

## Функциональность

| Раздел | Что делает |
|---|---|
| **Дашборд** | Стоимость портфеля во времени, структура по классам активов, пассивный доход, доходность против индексов, полученные выплаты по месяцам, ближайшие выплаты, ключевые метрики, макроэкономика (ключевая ставка, инфляция, ОФЗ), топ позиций |
| **Пассивный доход** | Сколько портфель принесёт деньгами за ближайшие 12 месяцев: сумма, средний платёж в месяц, доходность к рыночной стоимости и к вложенной сумме, разбивка на купоны и дивиденды, помесячный прогноз и вклад каждой бумаги |
| **Позиции** | Открытые и закрытые позиции: количество, средняя цена, рыночная цена, бумажная и реализованная прибыль, полученные выплаты, изменение за день. Цены обновляются вживую по WebSocket |
| **Сделки** | Добавление, правка и удаление операций: покупка, продажа, дивиденд, купон, амортизация, сплит, пополнение, вывод, налог, комиссия, проценты. Тикер ищется прямо на Мосбирже |
| **Календарь** | Ожидаемые купоны, амортизации, погашения и дивиденды по текущим позициям на горизонте до двух лет + история фактически полученных выплат. Наступившие купоны, амортизации и погашения зачисляются в сделки автоматически; любую выплату можно зачислить вручную кнопкой в строке |
| **Облигации** | По каждому выпуску: текущая доходность, простая к погашению, эффективная, дюрация Маколея и модифицированная, НКД, срок до погашения. Плюс средневзвешенные показатели по всему облигационному портфелю |
| **Метрики** | TWR, XIRR, волатильность, максимальная просадка, VaR и Expected Shortfall (95 % и 99 %), коэффициенты Шарпа, Сортино и Калмара, бета, альфа, корреляция, тепловая карта корреляций активов — на семи горизонтах сразу |
| **Бенчмарки** | Сравнение с IMOEX, MCFTR, RGBITR, RUCBTRNS, RUGBITR10Y + симуляция Монте-Карло для портфеля |
| **Активы** | Справочник инструментов, ручная синхронизация с биржей, создание кастомных активов (вклад, накопительный счёт) |

## Как считаются метрики

Ключевые соглашения — они определяют, что именно вы видите на экране.

### Денежный остаток и внешние потоки

Операции пополнения счёта заводят далеко не всегда. Без них денежный остаток ушёл
бы в минус, а TWR и XIRR посчитать было бы невозможно. Поэтому если на покупку не
хватает денег, недостающая сумма записывается как **внешнее пополнение в дату
сделки**. Явные операции `Пополнение` / `Вывод`, если вы их заводите, учитываются
как есть и не дублируются.

### TWR — доходность, очищенная от вводов и выводов

Дневная доходность считается как `r = V_t / (V_{t−1} + F_t) − 1`, где `F_t` —
внешний поток дня; потоки считаются пришедшими в начале дня. Дни цепляются
произведением. Для периода, начинающегося не с нуля, базой служит стоимость
портфеля на **предыдущий торговый день** — иначе месячная доходность считалась бы
от случайного платежа внутри окна.

Доходности считаются только по **торговым дням Мосбиржи**; потоки выходных
переносятся на ближайший торговый день. По календарным дням волатильность была бы
занижена нулевыми выходными.

К году доходность приводится только на окне от 30 дней — на более коротких
интервалах возведение в степень `1/years` превращает шум в тысячи процентов.

### XIRR — денежно-взвешенная доходность

Внутренняя норма доходности по датированным потокам: пополнения со знаком минус,
выводы и итоговая стоимость — со знаком плюс. Если период начинается не с нуля,
стоимость на его начало входит в поток как первоначальное вложение. Решается
методом Ньютона с запасной бисекцией.

TWR и XIRR почти всегда расходятся, и это нормально: TWR отвечает на вопрос
«как сработала стратегия», XIRR — «сколько заработали мои деньги с учётом того,
когда я их вносил». В шапке дашборда как основная цифра доходности показан
**XIRR** — он уже годовой и ближе к бытовому «сколько процентов я заработал»;
TWR остаётся рядом справочно и используется в сравнении с индексами, где важна
именно очищенная от пополнений динамика.

### Пассивный доход

Ожидаемые купоны и дивиденды по текущим позициям на 12 месяцев вперёд, из того
же календаря выплат. **Амортизация и погашение в доход не входят** — это возврат
тела долга; они показаны отдельной строкой, иначе доходность выглядела бы кратно
выше реальной.

По облигациям учитывается весь известный купонный график; у флоатеров
необъявленные купоны прогнозируются по последнему известному значению, и доля
таких прогнозов выводится рядом. По акциям учитываются **только уже объявленные**
дивиденды — ISS не знает о невыплаченных решениях, поэтому дивидендная часть
занижена. Налог не вычитается.

Доходность считается двумя способами: к текущей рыночной стоимости позиций
(«сколько процентов от сегодняшней цены портфеля вернётся деньгами») и к
себестоимости.

### Автоматическое зачисление выплат

Купоны, амортизации и погашения по облигациям попадают в **Сделки** сами:
фоновая задача при старте и далее раз в `AUTO_POST_INTERVAL_MINUTES` проверяет
календарь и создаёт операции по выплатам, дата которых уже наступила.

* Позиция проверяется на **дату фиксации реестра** (для купона), поэтому купон
  получит тот портфель, где бумага была на отсечке, даже если позже она продана.
* Если бумага лежит в нескольких портфелях, операция создастся в каждом из них.
* Проводятся только **подтверждённые** суммы. Прогнозные купоны флоатеров
  автоматически не зачисляются — их можно провести вручную кнопкой в календаре.
* Повторный запуск не создаёт дублей: операция ищется по внешнему
  идентификатору и по дате в окне ±5 дней. Если позже импортировать отчёт
  брокера с этой же выплатой, автоматическая запись заменится фактическими
  данными из файла.
* После простоя приложение «догоняет» выплаты за последние
  `AUTO_POST_LOOKBACK_DAYS` дней (по умолчанию 45), а не за всю историю.

Отключить автозачисление: `AUTO_POST_PAYMENTS=false`. Принудительно запустить
проверку можно кнопкой «Зачислить прошедшие» на странице календаря или
`POST /api/calendar/payments/auto-post`.

### Риск

* **Волатильность** — стандартное отклонение дневных доходностей × √252.
* **Максимальная просадка** — по накопленному индексу TWR, а не по стоимости
  портфеля: иначе пополнение счёта выглядело бы как рост, а вывод — как просадка.
  Рядом выводится длительность просадки в днях.
* **VaR (value at risk)** — исторический метод: граница, которую убыток не
  превышает с заданной вероятностью. VaR 95 % — квантиль 5 % худших дневных
  доходностей, VaR 99 % — квантиль 1 %. Знак отрицательный: `−2 %` значит
  «в худших 5 % дней убыток был не глубже 2 %».
* **Expected Shortfall (ES, CVaR)** — средний убыток за границей VaR. В отличие
  от VaR он учитывает, насколько глубоко провалился хвост, поэтому лучше
  описывает редкие тяжёлые дни.
* **Худший и лучший день** — экстремальные дневные доходности с датами.
* **Бета и альфа** — регрессия дневных доходностей портфеля на доходности индекса.
* **Шарп** = (годовой TWR − безрисковая ставка) ÷ волатильность.
* **Сортино** — то же, но в знаменателе только просадочная волатильность
  относительно безрисковой ставки.
* **Калмар** = годовой TWR ÷ |максимальная просадка|: сколько доходности
  приходится на единицу пережитой просадки.

VaR и ES считаются по дневным доходностям TWR и приводятся к году умножением
на √252 — это оценка масштаба риска, а не гарантия годового убытка. VaR/ES 95 %
появляются на истории от 20 торговых дней, 99 % — от 60: на коротком ряду
квантиль 1 % совпал бы с единственным худшим днём и ничего не говорил бы
о распределении.

Безрисковая ставка задаётся в `.env` (`RISK_FREE_RATE`, по умолчанию 16 % годовых)
и меняется прямо на странице «Метрики». При высокой ключевой ставке отрицательный
Шарп означает лишь, что портфель отстал от депозита.

### Корреляция активов

Внизу страницы «Метрики» — тепловая карта попарных корреляций открытых позиций.
Клик по ячейке открывает карточку пары: корреляция, ковариация за день и за год,
число общих наблюдений, веса и годовая волатильность обеих бумаг.

* **Корреляция** — Пирсон по дневным доходностям, от −1 до +1. Красный —
  бумаги движутся вместе (концентрация риска), зелёный — разнонаправленно
  (диверсификация). Значение всегда подписано числом, поэтому цвет вторичен.
* **Ковариация** — та же связь без нормировки. Показывается в «процентах в
  квадрате»: дневная и годовая (×252), чтобы числа не были микроскопическими.
* Берутся **чистые цены** без НКД: у облигаций грязная цена прыгает на купонной
  дате, и это исказило бы корреляцию с акциями.
* Доходности выравниваются по **общей сетке торговых дней Мосбиржи**; последняя
  известная цена протягивается вперёд. Пара считается по пересечению дат, когда
  обе бумаги уже торговались.
* В матрицу попадают до **15 крупнейших позиций** по рыночной стоимости. Пары
  с менее чем 10 общими наблюдениями не считаются — на таком окне корреляция
  была бы шумом.

API: `GET /api/portfolio/correlation?period=1Y&max_assets=15`.

### Симуляция Монте-Карло

На странице «Бенчмарки» — веер сценариев стоимости портфеля на горизонт 3 месяца,
полгода, год или три года.

* Дневные доходности **TWR** за выбранный период выбираются случайно и с
  возвращением (бутстрэп). Поэтому распределение сохраняет реальные «толстые
  хвосты» и асимметрию, которых нет у нормального распределения.
* Начальная стоимость — текущая оценка портфеля: позиции по рынку плюс деньги.
  Результат читается в рублях.
* На графике — медиана и полосы 25–75 % и 5–95 %; на карточках — вероятность
  убытка, VaR 95 % (граница, хуже которой 5 % сценариев) и ES 95 % (средний
  убыток за этой границей).
* Зерно генератора фиксировано: при одних и тех же данных и горизонте прогноз
  не «прыгает» между запросами.
* Для симуляции нужно не меньше 30 торговых дней истории. Будущие пополнения,
  выводы и изменение состава портфеля не моделируются.

API: `GET /api/portfolio/monte-carlo?period=ALL&horizon=1Y&simulations=1000`.

### Макроэкономика на дашборде

Блок «Макроэкономика» показывается, только если источники ответили. Все данные
бесплатны и не требуют ключей:

| Показатель | Источник |
|---|---|
| Ключевая ставка ЦБ РФ | DailyInfo SOAP `KeyRateXML` на `cbr.ru` |
| Инфляция г/г и цель по инфляции | месячная выгрузка «Инфляция и ключевая ставка» |
| Инфляция м/м | XLSX «Показатели сезонно сглаженной динамики потребительских цен» |
| Доходность ОФЗ | MOEX ISS, кривая бескупонной доходности `zcyc` |

Инфляция м/м публикуется ЦБ **с сезонной корректировкой** — так её и подписывает
карточка. Недельная инфляция не выводится: ЦБ публикует её только в новостях и
PDF, стабильного машинно-читаемого источника нет. Ответы кешируются на
`MACRO_CACHE_MINUTES`; если источник недоступен, соответствующий показатель
пропадает, а дашборд продолжает работать. Запросы к ЦБ идут на `https://cbr.ru`
без `www` — домен с `www` закрыт DDoS-Guard. Отключить блок целиком:
`MACRO_ENABLED=false`.

### Себестоимость и прибыль

Списание при продаже — **FIFO**. Комиссия и уплаченный НКД входят в себестоимость
лота. Амортизация номинала уменьшает себестоимость пропорционально и не считается
доходом от переоценки. Сплит умножает количество и делит цену.

Продажа ограничена остатком по портфелю: API не даст продать бумагу, которой нет
на дату сделки, или количество больше остатка. В форме продажи список содержит
только открытые позиции выбранного портфеля, а рядом с количеством показан
доступный остаток. Для исторической даты проверка выполняется по остатку на эту
дату, а не по текущему.

### Облигации

Все доходности считаются от **грязной цены** (чистая + НКД) по полному графику
купонов, амортизаций и погашения из ISS.

При добавлении покупки или продажи облигации **цена и НКД подставляются
автоматически**: приложение берёт чистую цену и НКД на дату сделки из истории
Мосбиржи, а для сегодняшней даты — из текущей котировки. Если поле уже заполнено
вручную, оно не перезаписывается. Отдельный запрос для формы:
`GET /api/assets/quote?secid=SU26238RMFS4&date=2026-11-20`.

* **Текущая доходность** — купоны за ближайшие 12 месяцев ÷ чистая цена.
* **Простая к погашению** — `(весь будущий поток − грязная цена) / грязная цена × 365/дней`.
* **Эффективная** — ставка, при которой дисконтированный поток равен грязной цене
  (то же, что Мосбиржа показывает как «доходность»).
* **Дюрация Маколея** — средневзвешенный срок возврата денег; модифицированная —
  Маколея ÷ (1 + доходность).

У флоатеров будущие купоны ещё не объявлены — они прогнозируются по последнему
известному значению, такие выпуски помечены как «оценка».

Котировки облигаций на бирже даны в процентах от номинала; внутри приложения они
переводятся в рубли с учётом уже прошедших амортизаций.

### Изменение стоимости за день

`day_change` — это изменение стоимости позиции в деньгах:

```text
day_change = (текущая чистая цена − чистая цена прошлого закрытия) × количество
```

Считаем **по чистой цене**, как в брокерском отчёте: НКД начисляется каждый
день и в дневное изменение не входит. Если подмешать НКД в базу, перед купоном
(когда ISS обнуляет `ACCRUEDINT`) получается ложный убыток на весь накопленный
НКД — именно так выглядел провал по RU000A10BY45.

База сравнения — **предыдущее закрытие**, а не цена покупки:

* для акций, фондов и облигаций это `PREVPRICE` — цена последней сделки прошлой
  сессии. Если ISS её не отдал, берётся `PREVLEGALCLOSEPRICE` (официальная цена
  закрытия);
* если `prev_close` в котировке нет (например, T-Invest API), берутся два
  последних закрытия из истории. В выходные, когда текущая цена совпадает с
  последним закрытием, предыдущим считается закрытие до него — иначе изменение
  было бы нулевым.

`day_change_pct` считается от той же базы. Если базы нет, используется
`LASTTOPREVPRICE` из ISS (после закрытия сессии `LASTCHANGEPRCNT` обнуляется,
поэтому он не подходит).

Почему числа могут отличаться от брокера:

* MOEX ISS без токена отдаёт данные с задержкой ~15 минут, а брокер — без неё;
  в момент сделки или сразу после открытия цифры закономерно расходятся;
* брокер может считать базой официальную цену закрытия, а не цену последней
  сделки. Приложение использует `PREVPRICE`, поэтому в выходные и после вечерней
  сессии возможна разница в несколько копеек на бумагу;
* в выходные текущая цена — последняя сделка пятницы, поэтому «за день»
  показывает изменение последней сессии.

Сумма `day_change` по позициям равна изменению чистой стоимости портфеля за день.

## Про «риалтайм» цен

Честная картина по бесплатным источникам:

| Провайдер | Задержка | Что нужно |
|---|---|---|
| **MOEX ISS** (по умолчанию) | ~15 минут | ничего, публичный API |
| **T-Invest API** | без задержки | бесплатный токен, выдаётся при наличии счёта в Т-Инвестициях |

Бэкенд опрашивает выбранного провайдера каждые `QUOTE_POLL_SECONDS` секунд,
складывает котировки в базу и рассылает изменения фронтенду по WebSocket
`/ws/quotes` — интерфейс обновляет цены без перезагрузки страницы. Индикатор
«онлайн» в шапке показывает состояние сокета.

Переключение на T-Invest:

```bash
# .env
QUOTE_PROVIDER=tinvest
TINVEST_TOKEN=<ваш токен>
```

Данных без задержки и без регистрации Мосбиржа не отдаёт никому — это ограничение
биржи, а не приложения.

## Кастомные активы

Для банковского вклада: **Активы → + Кастомный актив**, цена единицы `1`, ставка и
периодичность выплат. Затем **Сделки → Добавить → Покупка** этого актива, где
количество равно сумме вклада в рублях. Календарь ожидаемых выплат построится по
ставке автоматически; при включённой капитализации проценты вместо выплат
увеличивают стоимость актива.

## Разработка

```bash
# тесты расчётного ядра
docker compose exec backend python -m pytest tests/ -q

# новая миграция после правки моделей
docker compose exec backend alembic revision --autogenerate -m "описание"
docker compose exec backend alembic upgrade head

# фронтенд
cd frontend
npm run typecheck
npm run build
```

Ручное обновление рыночных данных: кнопка «Обновить всё с биржи» на странице
«Активы» или `POST /api/sync`.

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `POSTGRES_PORT` | `5433` | внешний порт БД |
| `BACKEND_PORT` | `8000` | порт API |
| `QUOTE_PROVIDER` | `moex` | `moex` или `tinvest` |
| `QUOTE_POLL_SECONDS` | `15` | период опроса котировок |
| `TINVEST_TOKEN` | — | токен T-Invest API |
| `RISK_FREE_RATE` | `0.16` | безрисковая ставка для Шарпа и Сортино |
| `SYNC_ON_STARTUP` | `true` | догружать историю индексов фоном при старте |
| `AUTO_POST_PAYMENTS` | `true` | автоматически зачислять наступившие купоны и амортизации |
| `AUTO_POST_LOOKBACK_DAYS` | `45` | на сколько дней назад догонять выплаты после простоя |
| `AUTO_POST_INTERVAL_MINUTES` | `60` | период проверки наступивших выплат |
| `MACRO_ENABLED` | `true` | показывать блок макроэкономики на дашборде |
| `MACRO_CACHE_MINUTES` | `180` | как часто обновлять макроданные |
| `MACRO_CBR_BASE` | `https://cbr.ru` | базовый адрес ЦБ РФ (без `www`) |
| `MACRO_OFZ_TENOR` | `10` | срок ОФЗ для основной карточки, лет |

## Ограничения

* Мультивалютность заложена в схеме, но переоценка ведётся в рублях —
  для инструментов в валюте курсовая переоценка не считается.
* Дата выплаты дивиденда оценивается как «отсечка + 10 дней»: ISS отдаёт только
  дату закрытия реестра.
* Простая доходность к погашению занижена для амортизируемых выпусков — она делит
  весь поток на полный срок до погашения. Для них ориентируйтесь на эффективную.
* Налог на дивиденды и купоны учитывается, только если он указан в операции;
  автоматического расчёта НДФЛ нет. Автозачисление тоже создаёт сумму до налога.
* Прогнозные купоны флоатеров автоматически не зачисляются: сумма по ним ещё
  не объявлена. Их можно провести вручную кнопкой в календаре и поправить сумму
  после публикации фактического купона.
